# WW-5791 Struts Boot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A newcomer adds one dependency, registers an action in Java, runs `main()`, and gets a FreeMarker page from embedded Tomcat. No XML, no Convention, no Spring.

**Architecture:**
- A new top-level `boot/` module with three parts:
  - a fluent registry that only records definitions
  - a `ServletContextAwareConfigurationProvider` that turns those definitions into ordinary `PackageConfig`s
  - a launcher that starts Tomcat, registers `StrutsPrepareAndExecuteFilter` with `configProviders=<provider>`, and passes the registry to the provider through a servlet-context attribute
- Core is untouched.

**Tech Stack:**
- Java 17
- Struts core 7.5.0-SNAPSHOT
- `tomcat-embed-core`: 10.1.x by default, 11.0.x under `-Pjakartaee11`
- FreeMarker
- JUnit 4, AssertJ, `java.net.http.HttpClient`
- `maven-shade-plugin` for the example app

**Spec:** `docs/superpowers/specs/2026-10-23-WW-5791-struts-boot-design.md`

## Global Constraints

- No file under `core/` changes. If something can't be done through existing extension points, stop and raise it.
- No Spring artifact in `struts2-boot-starter`'s dependency tree. Check with `./mvnw -pl boot dependency:tree`.
- Registry config must equal what the equivalent `struts.xml` would produce. Never relax strict method invocation, `@StrutsParameter` or the allowlist. Never set `struts.enable.SlashesInActionNames` or `struts.devMode`.
- Never read `application.properties`. Settings come from `struts.properties`, with Boot keys `struts.boot.port` (default `8080`) and `struts.boot.context-path` (default `""`). `--key=value` arguments override the file.
- FreeMarker only. Result paths resolve to `/templates/` + path on the classpath.
- Tomcat follows core's Jakarta line. Root property `tomcat-embed.version` is `10.1.59`, and `11.0.27` in the `jakartaee11` profile.
- Configuration errors are `org.apache.struts2.config.ConfigurationException`, thrown at startup.
- Tests are JUnit 4 (`org.junit.Test`). JUnit 5 is never used.
- Package: `org.apache.struts2.boot`. Artifact: `org.apache.struts:struts2-boot-starter`.
- Tomcat base dir: `Files.createTempDirectory("struts-boot-" + UUID.randomUUID())`, deleted recursively on close.
- Default to no comments (see `~/.claude/CLAUDE.md`). Every new file carries the ASF license header, copied from any existing source file.

## Review Focus

1. **Struts tags inside a template.** `<@s.property value="message"/>` must render. `FreemarkerManager` builds a `TaglibFactory`, which needs `jakarta.servlet.jsp` classes that `tomcat-embed-core` doesn't ship. Pinned in Task 4 `testStrutsTagRenders`.
2. **Startup failure leaves nothing behind.** A `ConfigurationException` or a busy port must not leave a running Tomcat, a hung JVM or a leftover temp dir. Pinned in Task 4 `testConfigurationErrorStopsTomcatAndCleansBaseDir` and `testBusyPortFailsCleanly`.
3. **Non-empty context path.** Actions answer under `/ctx/...`, and `redirectAction` carries the context path. Pinned in Task 4 `testContextPathAppliesToActionsAndRedirects`.
4. **`namespace("/admin")` called twice.** Both calls land in one package, and a duplicate name across the two calls throws. Pinned in Task 1 `testNamespaceDeclaredTwiceMerges` and `testDuplicateAcrossRepeatedNamespaceThrows`.
5. **Argument precedence.** `--struts.boot.port=9090` beats `struts.boot.port=8081` in `struts.properties`, and unknown arguments are ignored rather than fatal. Pinned in Task 3.

  - `public RegistryConfigurationProvider()`: used by `Dispatcher` through `configProviders`. `initWithContext` reads `ActionRegistry.SERVLET_CONTEXT_ATTRIBUTE`. If the attribute is missing, it throws `ConfigurationException`.

Translation rules (from the spec):
- Each package uses `addParent(configuration.getPackageConfig("struts-default"))` and the definition's namespace. `strictMethodInvocation` keeps its default (`true`).
- Each action is `new ActionConfig.Builder(pkgName, name, actionClass.getName())`, with `methodName(m)` and `addAllowedMethod(m)`.
  - If `httpMethodSet()` is non-empty, call `addHttpMethods(set)`.
  - The interceptor stack comes from the action first, then the namespace. If either is set, call `addInterceptors(InterceptorBuilder.constructInterceptorReference(pkgBuilder, stack, Map.of(), null, objectFactory))`. If neither is set, add no interceptors, so the package default (`defaultStack`) applies.
- A `TEMPLATE` result becomes `new ResultConfig.Builder(name, freemarkerClass).addParam("location", "/templates/" + path)`.
- A `REDIRECT_ACTION` result becomes `new ResultConfig.Builder(name, redirectActionClass).addParam("actionName", target)`.
- Result classes come from `strutsDefault.getAllResultTypeConfigs().get("freemarker" | "redirectAction").getClassName()`.

Validation, each a `ConfigurationException` thrown from `loadPackages()`:
- The template `templates/<path>` is missing on the classpath. Check with `ClassLoaderUtil.getResource`.
- An unknown stack name. `constructInterceptorReference` already throws this.
- A non-abstract package already in `configuration.getPackageConfigs()` has the same namespace and an action with the same name. The message names the namespace, the action and the XML package.

**Interfaces:**
- Consumes `ActionRegistry` (Task 1), `RegistryConfigurationProvider` (Task 2), and `BootSettings` (Task 3).
- Produces:
  - `public final class StrutsBoot`:
    - `static void run(Class<? extends StrutsBootApplication> app, String... args)`: starts the server and blocks on `await()`. On a startup failure it rethrows, which a newcomer's `main` reports as a non-zero exit.
    - `static StrutsBootServer start(Class<? extends StrutsBootApplication> app, String... args)`: returns once Tomcat is serving.

    - `int port()`: the actual bound port, which matters when `--struts.boot.port=0`
    - `String baseUrl()`: `"http://127.0.0.1:" + port + contextPath`
    - `Path baseDir()`
    - `void await()`
    - `void close()`: stops and destroys Tomcat, then deletes `baseDir`

`start` sequence, following the pattern in `JasperReport7TomcatTest`:
1. Instantiate the app with its no-arg constructor and call `actions(registry)`.
2. Create the temp base dir.
3. Create `new Tomcat()` with `setBaseDir` and `setPort`, then `addContext(contextPath, baseDir)`. Put the registry into the context's servlet context under `SERVLET_CONTEXT_ATTRIBUTE` (through a `ServletContainerInitializer` or `context.getServletContext().setAttribute` before start).
4. Add a `FilterDef` for `StrutsPrepareAndExecuteFilter` with init param `configProviders=RegistryConfigurationProvider.class.getName()`, mapped to `/*`.
5. Start Tomcat. If the context fails to start (`context.getState() != LifecycleState.STARTED`), or anything throws, call `close()` and throw a `ConfigurationException` that carries the cause.
6. Register a shutdown hook that calls `close()`. `close()` must be idempotent.
